# 剧情与画面审查记录

采用本仓冻结的 shuohao 写戏参考与 zenstory 去模板审片参考进行人工编排；未声称运行了完整上游 novel 项目、原生审片报告或真人艺术审批。

| 检查 | 本片的具体处理 | 边界 |
|---|---|---|
| 目标与阻碍 | 小林想讲清自己的贡献，却把“一个按钮”判断成不值得写。第一句追问提出这个矛盾 | 独立小品，非长篇反转爽剧 |
| 因果 | 找不到入口 → 去掉欢迎页、入口前移 → 虚构复测找到；没有用产品神奇生成答案解围 | 项目和次数明确虚构，不推断产品效果 |
| 选择与变化 | 前半使用“就改了个”，后半解释自己为什么做；最后准备重新开始 | 不加重复的成功学旁白 |
| 镜头目的 | 追问看反应；讲原因看原始记录；“太小了”切到记下判断的手；鼓励后回到近景 | 复用两个旧的合法高清原片，来源逐镜记录 |
| 字幕和声音 | 11句短台词，Serena 心声、Dylan 画外；停顿为实际生成时长之后留出的空间 | 没有口型同步；自动转写低置信，不作为字音/艺术通过证据，真人逐字听辨未运行 |
| 清晰度 | 新动态片均原生1280×704/24fps，实测高清 UI 为2560×1440；1920×1080是合成画幅 | 不将放大后的输出冒充原生1080p人物生成 |

观察到的质量问题及处理：

- S03 原片约第2秒后右侧出现不应有的蓝色背景块；完整原片保留并记录，未认定全画幅可用。剪辑使用 `crop=864:486:72:24` 的人物近景；逐秒取景和v2带字幕联络表未见这些背景块，未代替逐帧人审。
- 旧 closeup 在后半出现不计划的前景人影，只用早期干净区域；旧 native 只取写字手部，作为回忆插镜。没有使用旧512×288试算或伪称新拍。
- UI 大视野裁切会留下半截背景字，最终收紧到完整项目设置区；v2去掉v1后期绿框，只保留实际文本选择。原始录制内容/保存结果没有改写成虚假数据。侧面片段也裁去右侧异常背景区域，保留真实的抬手思考动作。
- S02 指令原计划移手到触摸板，模型实际生成抬手托腮；按迟疑镜头剪用，未宣称模型完全执行了指定动作。浏览器两轮显示丢帧均23/1230，文件完整解码通过，二者不是同一指标。

参考建议的适用取舍：上游偏连载剧情，建议少用心声、以运动钩子开篇和留结尾悬念。本片受可靠口型能力边界限制，选择明确标识的内心短剧形式，保留较多画外对白；以完整小矛盾收束，不宣称符合所有连载剧集门槛或专业艺术标准。最终审美结论由用户审看决定。
