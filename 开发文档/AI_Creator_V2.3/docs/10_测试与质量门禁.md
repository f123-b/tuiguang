# V2.3 测试策略与质量门禁

## 1. 测试金字塔
- 单元：业务状态转移、数据验证、去重/预算/权限；高速、确定性。
- 契约：OpenAPI、Shot Provider、VideoProjectIR、运行回执、错误码；不同服务独立变更依旧兼容。
- 集成：PostgreSQL、对象存储、队列、通知、模型网关；使用受控测试凭据与隔离环境。
- Agent 评测：事实幻觉、工具越权、指令注入、低质量广告、选题重复、用户修改偏好学习；有版本化数据集。
- 视频：真实 FFmpeg 媒体分析（分辨率/帧率/时长/音轨/黑帧/字幕安全区）+ 可编辑性和局部重渲染。
- E2E：创建创作者、7/30 日受控时钟、实际内容导出、人工发布登记、真实用户导入数据、复盘。**不使用社媒真实账号自动发帖测试**。
- 混沌/故障注入：Worker 进程崩溃、渲染器 OOM、网络超时、重复消费、错过日更窗口、模型返回不合规范 JSON。

## 2. 每次 PR 必须通过
基础规范/语法、业务单测、受影响模块契约测试、权限/安全红线测试、变更影响相关集成用例；前端页面有渲染检查和无障碍关键流程；新增 API 必须更新 OpenAPI。未通过不得自动合并。对于 GPU 实测成本高的用例可在 staging 夜间回归，但发布包含此类变更时必须经过相关真实渲染验证。

## 3. 金标准测试清单
| 用例 | 通过条件 |
|---|---|
| 一天并发触发三次 | 同个 creator_id/日期/slot 只创建一条业务任务 |
| 7 日暂停/恢复 | 暂停后不启动新的有费用任务；恢复先检查预算 |
| 软件新功能未发布 | AI 不把未核实信息写入对外事实 |
| 修改第 3 镜头 | 只重渲染依赖镜头；其余素材 hash 不变 |
| 模型请求计费超时 | 未查清外部结果前不得盲目重试扣费 |
| Prompt 新版本 | 同固定测试集对比事实、工具安全、成本与内容多样性 |
| 手动发布 | 产品无第三方平台自动 POST、自动登录、自动评论功能 |
| 用户登记发布 | 数据库 `source=user_reported`；无官方已验证标记 |
| 真实数据缺失 | NULL/unknown，不伪造为 0；不得推断增长趋势 |
| 安全恢复 | 旧版本长任务可以继续/明确提示升级阻断，不能悄然丢失 |
| 严重故障 | 可根据 trace_id、error_code、实际版本定位错误阶段 |

## 4. AI 评测数据集
- 每个数据集带 `dataset_version`、有效品牌事实版本和人工标注依据。
- 指标：事实准确率、营销不实率、重复率、人工首次通过率、平均改稿次数、单片成本和方案多样性；指标可分平台/形式，不能只用一个综合分掩盖重大质量问题。
- Prompt 实验必须保持同一组样例、同等约束和可比成本；随机模型重复采样/置信区间应说明，而非一次结果就宣布显著改善。
- 用户上传真实素材做评测前须明确授权并脱敏；禁止将客户机密隐式送进第三方评测服务。

## 5. 人工发布安全门禁
必须验证：无社媒平台凭据存储页面、无浏览器自动发帖任务、无第三方发布接口、无隐蔽脚本读取 Cookie。**字符串扫描只是辅助**，还要进行依赖审计、网络层 egress 访问控制和真人代码复核。人工操作指南按官方客户端流程，不制作可绕过平台规则的脚本。

## 6. CI 设计包的真实状态
本交付包提供 `.github/workflows/engineering-quality-template.yml`：仅检查文档/示例脚本/原型 JS，不会验证尚未存在的正式 API/渲染 Worker。**接入真实代码后必须增加前端/后端/Agent/渲染/数据库真实工作流并设置 branch protection 必需状态检查**，否则不能标为正式生产门禁。提交 PR 时显式列出没有执行的测试。

## 7. 上线前独立验收
至少使用一个真实授权的软件品牌完成 14 天受控持续创作、3 类真实成片、人工发布资料包、用户自报发布、一次授权官方数据导入、一次周复盘，并演练 API/worker 宕机与恢复。支付/多租户要另做威胁建模与成本压力测试。
