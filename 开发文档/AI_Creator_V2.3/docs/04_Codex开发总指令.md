# Codex 总开发指令（可直接复制）

## 你的角色和交付要求

你现在是 AI 持续创作者商业软件的主架构师、前端设计负责人、全栈工程师与测试工程师。项目根目录 `docs/` 包含：
- `01_产品完整开发方案_人工发布版.md`
- `02_完整UI_UX设计规范.md`
- `03_用户使用手册.md`
- `04_Codex开发总指令.md`
- `05_修订影响清单.md`

`prototype/` 是交互原型，仅含明确标注的假数据，不能把它直接当作正式应用的已完成功能。

**完整阅读上述文档，优先遵循本文件以及 01 的人工发布铁律**。不要延用以前方案中“自动发帖、平台 OAuth 代发、Chrome 自动上传、自动拉取私信/数据”的旧设计。

## 一、产品一句话

用户配置一次品牌、创作者人设、运营频率与预算，AI 之后长期按日自动生成真实的软件图文和宣传视频，预审并准备素材包；用户在第三方平台官方客户端/官网自己上传发布；回到本软件登记并导入平台官方数据，AI 每周根据真实反馈迭代未来的选题和内容策略。

## 二、最高优先级：任何阶段不得自动对外平台发帖

**禁止实现**：社媒登录凭据存储、浏览器自动点击发布、社媒发布 API POST、验证码处理与绕过、Cookie 复用、批量私信、刷赞刷评、后台爬取社媒数据。**不创建任何可由 LLM 调用的 `publish.submit` 工具**。对外发布的最后一步只能由用户在第三方平台自行操作。不得把 “准备发布包成功” 或 “用户登记已发布”写成“平台验证成功”。

正式页面主按钮：“审核”“准备发布包”“下载素材”“复制文案”“打开官方发布入口”“我已手动发布”。

**人工发布之后的学习闭环仍要做全**：用户登记实际发布时间/作品 URL（可选），上传或录入真实指标，AI 生成有证据的周报。

## 三、优先执行的工作与阶段

1. **M0 基础审计和设计**：检查仓库现状；核验各 OSS 许可证；建立 `LICENSE_INVENTORY.md`；按 UI 设计规范列出 32 个页面的路由、组件与接口；先做双引擎视频 PoC（真实软件录屏/MG + 素材混剪，各完成一条短片）；建立 OpenAPI、数据库 migration 与单元测试；禁止用假服务宣布成功。
2. **M1 持续创作者**：创建品牌和 AI 创作者，保存时区/频率/预算；用持久化任务引擎做每天自动策划和生成任务，含暂停/恢复/跳过/跨天恢复、状态和成本记录；7 天虚拟时钟与重启恢复测试。
3. **M2 图文与选题**：内容栏目、14 日滚动日历、语义去重、真实事实引用、图文封面编辑、平台差异版本和内容合规报告；全 UI 可使用。
4. **M3 宣传视频**：真实 UI 素材、6 类以上宣传视频制作模式、镜头级结构化分镜、时长和比例、渲染、音效/字幕、局部修改、1080p MP4 导出。先验证主视频底座再进行大量封装。
5. **M4 人工发布中心**：编排准备发布包、标题/正文/封面/视频下载、平台人工操作指南、AI 标识检查表、用户手动发布登记、每日提醒。必须通过“零自动发帖网络请求”测试。
6. **M5 数据与成长**：用户 CSV/XLSX/手工数据导入、来源与时间窗、真实分析、周报、策略建议审批、长期记忆、下周选题受反馈影响。缺数据不能编造数字。
7. **M6 系统体验/商业化**：帮助中心、使用手册嵌入、模型设置、预算、通知、账单、响应式和权限测试。
8. **M7 真实用户试点**：邀请真实用户对 14 天连续内容闭环进行验收，记录修订和问题；禁止伪造试点数据。

## 四、必须遵守的前端规范

参考 `02_完整UI_UX设计规范.md` 的 32 项页面、Mac/iOS 色彩和响应式。复用 `packages/ui` 的组件，所有主业务页面都有加载、空状态、失败和限权说明。原型 `/prototype/index.html` 可用于对照布局和术语，但必须替换演示数据、绑定真实接口。

每一个重要按钮都必须有业务行为：点击暂停实际写入持久状态；点击导出必须得到真实文件；点击“我已手动发布”保存 `user_reported_published`，不对接平台自动发帖；点击导入验证真实数据和来源；点击复盘有可追溯证据。

## 五、架构与工程

- Web：Next.js + React + TypeScript；必要时 Tauri 同一 UI；API：FastAPI；Agent：LangGraph；持续调度：PostgreSQL + Celery（或经 M0 评估后的 Temporal）；数据库：PostgreSQL + pgvector；对象存储：S3 兼容。
- 视频 Worker：以 OpenFilm + FFmpeg 作为统一编辑/合成候选，Motion Canvas 提供 MG，MoneyPrinterTurbo 提供自动短视频编排参考，ComfyUI/Wan 与 Blender 作为可选独立镜头服务。实现 Shot Provider/Scene IR，支持混搭，逐引擎核验许可证。
- 每个工具有风险分级、权限、输入输出 schema、幂等键、超时和预算。
- HiveMtk **仅参考** ToolGuard、审核、SOP、CRM 思想；AGPL 代码不得在未经许可时直接纳入闭源核心。
- 不允许将用户社媒账号 Token、Cookie 或验证码作为任何集成需求。品牌知识库事实要有来源，AI 不得直接修改用户锁定内容。

## 六、状态约束

创作者：`draft|active|paused_by_user|paused_by_budget|paused_by_policy|paused_by_error|archived`。

内容：`scheduled|topic_selected|draft_generated|asset_rendering|quality_check|compliance_review|awaiting_user_review|approved_for_handoff|export_package_ready|awaiting_manual_publication|user_reported_published|user_skipped|expired|metric_data_pending|analyzed`。

`user_reported_published` 必须存 `source=user_reported`，在 UI 文案里写“用户自行登记，未经平台验证”。所有真实指标都保存 `data_source`, `observed_at`, `metric_window`，缺失是 NULL 而非 0。

## 七、全局安全测试

- 静态和动态扫描都确认没有社媒自动发帖脚本/接口/SDK 调用/浏览器 Cookie 管理。
- 所有创建、导出、发布记录、导入数据接口有租户归属和权限校验。
- 生成内容事实引用可追踪；不允许凭空创造软件功能和虚假用户评价。
- 视频 AI 标识、版权与平台风险需要用户手工复核，不宣称“保证不封号”。
- 渲染和模型费用有预算上限，AI 无权自行提额。
- 用户暂停后不会出现新的高成本任务或站外副作用；恢复可追溯。
- UI 和帮助文档中的术语一致，无“自动发帖”残留入口。

## 八、每阶段交付格式

每阶段必须提交：
1. 真实代码与模块说明；
2. 数据库 migration / OpenAPI 契约；
3. 32 页 UI 中本阶段实际完成的页面清单与截图；
4. 单元、集成、E2E 测试报告，以及命令和实际输出；
5. 视频可实际渲染输出时必须提供可播放成片和源项目；
6. 完成/未完成/风险清单；
7. 使用手册中需要更新的章节与真实可操作步骤；
8. 下一阶段任务和拒绝发布边界的自动化静态检查结果。

## 九、第一轮直接执行

不要反复要求确认已经确定的设计决策。先读取当前仓库与全部文档，做代码/许可证/接口/UI 与实际状态审计；输出开发任务表与系统拓扑；完成 M0 的基本工程脚手架、数据库、认证、内容任务基础模型和多引擎视频渲染技术 PoC，所有新模块必须跑真实测试。若某个上游开源项目不可复用，立即记录依据并使用许可兼容的备选实现。**绝不为了进度伪造完成状态。**


## 九、V2.1 最高优先级更正：全类型 AI 宣传视频

**不得把产品定位成 CG 专用工具。** CG 只是可选择的一类镜头。请按 `docs/01_产品完整开发方案_人工发布版.md` 第 10 章、`docs/02_完整UI_UX设计规范.md` 第 11 章、`docs/03_用户使用手册.md` 第 15 章实施。

1. 实现统一 `VideoProject / Shot / MediaAsset / EngineProvider` 数据结构、分镜编辑 API、统一时间线。
2. 首批提供：2D/MG、录屏讲解、素材混剪、AI 创意片段 Provider 接口、混合宣传视频。3D 和连续卡通人物增加为可选高级引擎，不得假称第一版已全部可用。
3. 选型：OpenFilm（MIT）主底座候选；MoneyPrinterTurbo（MIT）自动短视频链路；Motion Canvas（MIT）MG；ComfyUI（GPL-3.0 独立服务）+ Wan（Apache-2.0 仓库，另核权重）生成式片段；Three.js/Blender 3D 增强。OpenCut 新架构仅研究；Remotion 的商业自动化使用需另核许可。
4. 在 UI 创建视频时支持 AI 推荐与模式手选；单镜头可换引擎，并明确显示预算、版权、真实素材、生成式标识和错误状态。
5. M0 必须产出两种引擎制作的最小混合视频原型；M3 至少具备三种可真实运行的视频形式，并预留更多引擎接入；不能以静态 UI 示意作为真实视频生成通过。
6. **绝不接入 MoneyPrinterTurbo 的社媒直接发布功能；用户自行下载并在官方平台手工发布**。
7. 把 UI 和手册中“只做 CG”“只能用真实 UI”“必然不是真人”等不准确表述修正为适用于不同内容形式的准确要求：真实功能仍须真实证据；AI/卡通/混剪可以使用授权素材。
