# 诊断与维护控制台 UI 规范（工程后台，非面向普通创作者）

## 设计目标
延续产品已有的 Mac/iOS 极简深浅色设计，**不新增一堆独立弹窗**。在系统管理内增加“诊断与维护”，默认仅管理员/开发者可进入；普通用户在任务详情看到最小必要故障说明与客服诊断码。

## 页面路由
- `/ops/diagnostics` 诊断总览：任务成功率、异常队列、Top Error Code、引擎可用性。
- `/ops/diagnostics/:run_id` 执行链：Trace Timeline（API → Agent → Video Worker → Export），镜头标记与错误证据。
- `/ops/releases` 版本中心：当前/上次稳定版本、版本清单、部署环节及灰度状态。
- `/ops/releases/:release_id` 发布详情：代码 SHA、DB、Prompt、模型、渲染器、素材/模板兼容矩阵。
- `/ops/maintenance` 维护中心：依赖安全问题、备份恢复检查、待升级模型、磁盘成本与清理策略。
- `/ops/incidents` 故障工单：严重程度、根因证据、影响范围、临时缓解、验收复盘。

## 诊断详情布局
顶部：任务名称 / 当前状态 / `creator_run_id` / 开始时间 / 所属工作区 / `release_id` / “复制脱敏诊断编号”按钮。
中部左：可视阶段树（选题、脚本、分镜、镜头生成、合成、技术 QA、人工发布包）；失败处高亮并给出**经过验证的错误码**。
中部右：失败镜头卡（Shot 03）、Provider、失败时间、资源指标、重试次数、**成本**、输出资产/日志哈希。
底部 Tabs：证据日志、版本对比、故障建议、相似历史工单、处理记录。
按钮：`重新生成失败镜头（需权限与预算确认）`、`复制诊断编号`、`导出脱敏诊断包`、`暂停创作者`、`转人工排查`。
所有按钮均有真实权限与操作逻辑；原型中的“恢复/重试”不能执行生产副作用。

## 状态语义
| 状态 | UI 展示 | 行为 |
|---|---|---|
| `unknown` | 未知/证据不足 | 禁止建议直接覆盖旧产物 |
| `identified` | 已发现失败阶段 | 给出确切错误阶段及证据 |
| `hypothesized` | 候选原因 | 明确写“推测”与待验证步骤 |
| `verified` | 根因验证通过 | 允许提出有权限的修复流程 |
| `mitigated` | 已缓解 | 需要留工单，非根治完成 |
| `resolved` | 已解决 | 必须有修复 PR 与测试证据 |

## 隐私与安全
前端不显示 Prompt 原文、密钥、用户私有文件路径和非本租户日志。诊断包必须脱敏并带过期权限；即使管理员也不能直接下载平台账号 Cookie（本系统不应存储）。发布按钮全部为用户自己完成发布的提示，不出现社媒自动发帖入口。

## 原型与实际区别
V2.3 提供 `/ops/diagnostics` 静态页面示例，展示**虚构的**故障条目与技术字段，用于 UI 评审。它不读取真实 Trace，不含真实用户生产数据，不代表可观测系统已部署。
