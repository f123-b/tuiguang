# Codex 执行指令：AI 原生工程与长期维护（V2.3）

你要维护的是一款长期运行的 AI 创作者产品：持续选题、图文制作、各类型宣传视频、人工发布包、真实数据导入和运营学习。现有 V2.1 产品方案与 V2.2 优化方案均有效，V2.3 的工程治理要求是新增的全局硬约束。

## 第一步：识别真实项目状态（不能先假设已经实现）
1. 查看仓库分支、主要目录、构建配置、Docker、任务执行入口、数据库、已有 CI；不要修改其他 GitHub 仓库。
2. 对照 `AGENTS.md`、`PROJECT_STATUS.md`、`docs/architecture/MODULE_MAP.md` 与现有源码，更新准确文件映射；如不存在代码，则标为未实现。
3. 分别核实 API、Agent、素材/视频渲染 Worker、调度器、数据导入与人工发布链路；更新受影响模块的接口说明。
4. 检查许可与技术栈，严禁从 HiveMtk 的 AGPL 代码直接复制进入闭源核心，未经核验不得声称商业许可兼容。

## 第二步：落实 P0 工程基线
- 统一 `trace_id`, `request_id`, `creator_run_id`, `content_id`, `video_project_id`, `shot_id`, `render_job_id`, `error_code`。
- 在真实服务接入 OpenTelemetry（支持自动上下文传播），对每一镜头处理记录实际 Provider 名称、回执、版本和费用。
- 定义错误码、结果 DTO 与 schema；前端错误视图分清观察事实和推测原因。
- 在真实仓库实现 CI 测试：业务/权限/契约/数据库/Agent/视频黄金样例等。此包内 CI 示例只是启动模板。
- 创建 Release Manifest，包括应用/Git/DB/Agent/Prompt/模型/Provider/视频模板/IR 版本，任务启动时冻结相应版本引用。
- 实现受控的重新执行：任务失败只重跑失败/安全的步骤，不能盲目重复支付模型费用，不能重启时生成两个相同日更任务。

## 第三步：逐阶段交付
每次变更先提交任务卡+最小失败测试/证据，再实现代码、运行测试、更新文档和 changelog。发布前输出“本次实际验证的结果”；没跑的测试必须标为未运行。生产发布、数据库危险操作和付费服务调整均需明确人工审批。

## 第四步：关键业务禁令
- AI 自动制作和审查内容，用户本人到社媒官方页面进行最后发布。
- 不实现社媒自动登录、自动点击发布、批量私信评论、Cookie 采集或绕过平台限制。
- 运营指标必须来自授权数据或用户导入；不编造阅读/播放/转化。
- 用户锁定的品牌事实与已确认素材不能被 Agent 擅自篡改。
- CG 只是宣传视频中的一种表现方式，不得删除 MG、录屏、混剪、卡通和 AI 生成场景的独立引擎方案。

## 第一轮任务交付
先完成 ENG-001~ENG-003 及 ENG-005 的真实系统方案，再按代码现状实现一条“创作者日更 → 视频/图文 → 审核 → 人工发布包 → 用户登记 → 数据导入”的可追踪闭环。对于实际有问题的部分先复现，修复后用同一输入验证不再复现。不要将工程模板视为现成的生产监控或 CI 成果。
