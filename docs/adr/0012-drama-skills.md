# ADR 0012：软件内置可审计的短剧技能与制作计划

状态：实施（用户 #47 授权）；不涉及生产发布。

观察：#45 的生成队列只接受孤立动作提示词，没有故事级人物目标、因果、场景走位或镜头覆盖契约。用户否定实际影片的逻辑与清晰度；1280输出并不证明源细节清晰。无法据此断言模型是唯一原因。

方案：新增独立 DramaProject（DB0016）保存原创/授权故事要求、可编辑结构化计划、技能冻结摘要、逐镜生成绑定及编辑回执。内置固定提交的 shuohao 七技能与 zenstory 审片技能，保留 LICENSE/NOTICE 和逐文件哈希。不是运行任意用户脚本的插件系统。第三方命令/云接口不授予任何权限。模型仅接收固定参考文本和受限 JSON 契约，不执行技能中的 Shell/Task/网络指令；确定性剧本检查由固定 Node 入口调用已审代码。

调用链：工作台→drama_api→drama（计划/连续性检查）→drama_jobs（共享 Run、授权、预算、模型配置冻结）→model_gateway。明确确认计划之后，每次仅提交一个已显示参数的镜头→既有 video_generation。所有镜头完成、来源仍有效、高清源尺寸与用户审看合格才进入既有 Recipe→Narration→Preview→人工复核→高清。不自动造角色参考图、不把人物台词当口型已实现。单次最多12镜/60秒，支持真人/动漫。

兼容与影响：新增表不修改旧 IR/Shot/引擎；旧孤立镜头入口保留。Prompt drama_skills@1；skill_registry@1；冻结上游 commit 和清单哈希。GPU生成仍单独确认、本机慢速，不新增服务费用；规划复用当前工作区模型预算。API工作区隔离，乐观修订锁；修改计划使旧绑定失效，不静默重发。原作权利和媒体质量仍需用户确认，规则通过不等于剧情好看或许可全部通过。

验收：先失败契约；权限、失效、因果与走位、台词时长、低清源阻断、未知回执不重发、旧视频与预算回归；第三方Windows自测；浏览器实际计划编辑与检查。回滚先暂停任务并保全0016数据库/新增资料，将匹配的迁移前0015备份恢复到独立路径，再使用6d6ec05源码验证后切换；旧源码的Alembic不认识0016，不能仅切Git后直接运行新数据库。禁止破坏性downgrade或伪造迁移版本戳。0016后新增计划不会自动进入旧数据库，必须另行导出保留。
