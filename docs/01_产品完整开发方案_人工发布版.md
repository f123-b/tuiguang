# AI 持续创作者 · 完整产品与开发方案

**版本**：V2.1 · 2026-11-05 · 人工发布定稿基线  
**范围**：产品需求、工程架构、宣传视频制作、长期学习、合规、人工发布、交付排期、验收契约  
**配套文档**：`02_完整UI_UX设计规范.md`、`03_用户使用手册.md`、`04_Codex开发总指令.md`、`05_修订影响清单.md`；`../prototype/index.html` 为离线可运行的前端交互原型。

> **一票否决原则**：本产品不自动登录、点击、上传、发布到小红书/抖音/闲鱼等第三方内容平台，不模拟人为操作，不绕平台验证码/风控，不提供批量私信与刷互动能力。所有对外公开发布由**用户本人到平台官方客户端或官方网站手动完成**。产品仅负责自动持续创作、发布资料准备、风险自检、发布提醒、手工发布登记与基于合法数据的学习。若未来探索某个平台的官方授权接口，也不得在此版本暗中启用，须经过单独产品设计、规则审查和用户明示同意。

## 1. 产品定义与商业价值

**一句话**：为软件产品养成一个长期工作的 AI 内容创作者——只需设置一次品牌和创作目标，系统每天生成可发布的图文和 软件宣传视频，用户在平台官方界面自行发布，再把真实效果反馈给 AI，持续改进未来的选题和内容。

**双模式**：
- **持续创作者**（默认主入口）：用户设置产品、目标受众、创作频率、内容栏目和预算；服务端长期调度每日创作和周复盘，支持暂停/恢复。
- **单次创作工具**：临时让 AI 做一篇图文、一张封面或一条 宣传视频，不影响长周期任务的历史与学习配置。

首个垂直场景限定为**软件产品运营**：SaaS、桌面软件、App、AI 工具及独立开发者；商品营销/闲鱼仅保留素材方案与未来扩展接口，不纳入 V1 核心营销承诺。第一版只支持**一个品牌、一个创作者**的完整闭环，之后再扩多品牌、多账号。

**承诺边界**：承诺持续创作的流程能力与可追溯的成品质量，不承诺流量、转化、推荐位或账号绝对安全。人工发布能降低第三方自动化操作风险，但内容仍要符合平台当时的规定；平台仍可能限制或处理账号。

## 2. 不可变业务原则

1. **人机责任分离**：AI 能做选题、素材、各种宣传视频、合规建议、导出包、提醒、数据分析；**用户独立执行所有外部平台发布动作**。
2. **无平台登录凭证**：V1 不采集、不存储社媒 Cookie、Token、密码、浏览器会话、二维码登录态。平台只用于选择内容规格、保存公开作品链接及用户自报的账号备注。
3. **合规先于导出**：对文字、画面、声音、产品宣称、著作权与 AI 生成标识做预审；硬性风险会阻止“一键发布包准备完成”，允许用户编辑并重新检测。导出原始私有素材如需提供，应明确标注未审核，不可包装成合规通过。
4. **真实软件功能**：展示软件 UI 时必须来自用户提交/获授权的真实截图、录屏与产品事实库；不能虚构软件功能、版本、用户好评或性能指标。
5. **长期成长≠无限上下文**：品牌事实、人设风格、内容历史、真实指标、学习结论分开存储；单日 LangGraph 独立运行，按需检索长期记忆。
6. **明确数据来源**：平台数据只来源于用户手工录入、上传的官方报表、未来单独批准的官方分析接口，或自有站点合法埋点。未收到数据就标记“缺失/未导入”；不抓取私密后台，也不推断凭空数字。
7. **用户最终控制**：用户可以暂停创作、跳过一天、修改计划、重做视频、拒绝策略更新、删除记忆、导出项目文件与发布记录。
8. **许可证边界**：HiveMtk AGPL-3.0 只做架构研究和独立实现参考；未经法务审查/许可，不直接拷贝其源码进入闭源商业项目。

## 4. 用户故事与成功路径

### 4.1 首次使用（10 分钟目标）
1. 注册/登录 → 新建品牌“有招”。
2. 上传 Logo、产品简介、功能清单及**真实软件截图/录屏**，标记哪些证据已核实。
3. 创建 AI 创作者：选择“理性科技博主”风格、平台、小红书图文/抖音宣传视频、每周频率、预算和时区。
4. AI 生成未来 14 天选题与第一个内容包，用户可编辑或锁定品牌事实。
5. AI 审核并准备发布包，用户在官方 App/创作者后台自行发布。
6. 用户回到本软件，登记平台、发布时间及真实作品链接；后续手动导入数据。
7. AI 复盘并将建议写入下次选题；用户能查看“依据何在”。

### 4.2 日常零输入（不是零人工）
每日后台自动创作，用户只需处理“待审内容/待手动发布”的任务；无需每天发指令。用户不处理时作品保持待办，不会被程序代发。可以设置“每日只通知一次”或“每周集中审核”。

### 4.3 例外
预算不足、产品事实过期、视频合成失败、合规未通过、素材版权不清 → 任务暂停于明确节点，通知用户，不能用低质内容自动顶替日更配额。

## 5. 信息架构与全局导航

一级导航：
1. **总览**：今日任务、AI 活动、待审待发、预算、学习摘要。
2. **我的创作者**：创作者详情、人设与频率、暂停恢复、运营目标、日程。
3. **选题与日历**：内容栏目、选题池、系列连载、14/30 天日历。
4. **内容工作室**：AI 图文编辑、封面模板、平台差异版本、素材来源。
5. **AI 宣传视频工作室**：镜头/轨道/场景、预览、动画参数、音轨与导出。
6. **人工发布中心**：待发布包、合规报告、平台手动操作清单、发布记录。
7. **数据与成长**：导入指标、内容效果、选题复盘、策略版本、长期记忆。
8. **品牌与素材**：真实功能证据、品牌定位、Logo/截图/录屏、版权信息。
9. **通知中心**：待审批、今日待发、生成失败、超额提示、报告可读。
10. **设置**：模型 Key、预算、通知、时区、隐私、计费、团队（后续）。

辅助入口：“AI 助手”浮动入口，以对话操作当前业务，但不替代上述结构化页面。完整 32 个页面/弹窗的交互和响应式布局见配套 `02_完整UI_UX设计规范.md`。

## 6. 工程架构（人工发布版）

```
    Next.js/React Web ───── Tauri Desktop (仅文件/录屏/本地预览)
                  │                  │
                  └──── FastAPI ─────┘
                          │
               Auth / Workspace / RBAC
                          │
       ┌──────────────────┼────────────────────┐
       │                  │                    │
  Brand + RAG     Continuous Creator     Manual Publish Hub
  Content Studio  Persistent Scheduler   Package / Checklist
       │                  │                    │
  LangGraph Agent    Daily Run Jobs       User-Entered Records
       │                  │                    │
   Video Renderer     Compliance            Metrics Import
 (OpenFilm* / SVG /        │                    │
  Three.js / FFmpeg) ──────┴──────> Analytics + Strategy Memory
                           │
                 PostgreSQL + pgvector + S3
```

`*` **技术验证门**：OpenFilm 先通过多轨可编辑 PoC；同时独立验证 Motion Canvas 的 MG 渲染和 MoneyPrinterTurbo 的素材/配音流水线。ComfyUI/Wan/Blender 为独立工作进程，通过 Shot Provider 对接；Remotion 若使用须核商业自动化许可。

**不需要的基础设施**：社媒账号登录守护进程、Chrome 登录态桥接、第三方平台自动发布连接器、私有 API 签名逆向库、自动评论/私信机器人、发布回执轮询器。

- 前端：Next.js + React + TypeScript + TailwindCSS + 组件库；设计 Tokens 统一 Web 和 Tauri。
- API：Python FastAPI + Pydantic；结构化日志、OpenAPI 与权限审计。
- Agent：LangGraph；单日任务读取创作者配置和相关记忆；写操作走确定性服务工具。
- 调度：先用 Postgres 持久计划 + Celery Beat/Worker（适合低运维 MVP），支持唯一日任务键、时区与错过任务处置；高规模再升级 Temporal，不允许 Web 内存定时器。
- 视频：OpenFilm 统一编辑与时间线，Node.js 多轨渲染 Worker + FFmpeg；Motion Canvas 负责 MG、MoneyPrinterTurbo 为素材+配音流水线提供参考，ComfyUI/Wan 和 Blender 为可选独立生成 Worker；按镜头缓存，任何生成镜头都不得伪造真实产品 UI。
- 数据：PostgreSQL；pgvector 仅辅助相关历史检索；S3/MinIO 存素材、成片、项目工程包。
- 模型：统一 OpenAI-compatible 模型网关 + BYOK + 限额；真实内容不得未经同意上传外部模型。
- 可观测：任务日志、错误告警、预算、资产引用与导出流水。

## 7. 持续创作者运行模型

**创作者状态**：`draft` → `active` ↔ `paused_by_user` / `paused_by_budget` / `paused_by_policy` / `paused_by_error` → `archived`。

**单日制作状态**：
```
scheduled
  -> topic_selected
  -> draft_generated
  -> asset_rendering
  -> quality_check
  -> compliance_review
  -> awaiting_user_review
  -> approved_for_handoff
  -> export_package_ready
  -> awaiting_manual_publication
  -> user_reported_published | user_skipped | expired
  -> metric_data_pending
  -> analyzed
```

**特别重要**：没有 `auto_submitting`、`platform_review_by_agent`、`auto_published`、`publish_attempt_retry` 等自动发帖状态。`user_reported_published` 仅表示用户自己确认“已在平台发布”，**不是程序向平台核验的官方回执**。用户可以添加链接和截图作为证据，但页面应明确标记数据来源。

**长期调度**：每天/每周按照创作者时区触发；支持“今日跳过”、“假期暂停”、“批量提前生成”；同一日期/栏目/平台具有唯一键；重启恢复；并发创作受费用与渲染队列控制。任何场景都不会触发站外发布。

## 8. 创作策略与长期记忆

五类记忆：
- 品牌真实事实（功能、定价、系统要求）：来源 ID、有效版本、用户锁定，AI 不得自改。
- 内容风格偏好：语气、配色、片头/片尾、禁词、创作范例。
- 作品历史：主题、栏目、标题、视频配方、渲染版本、导出时间、用户自报发布时间。
- 真实指标：来源、观察时间、统计窗口、导入文件与可比性。
- 策略假设：提出者、证据 ID、置信度、启用时间、结果、是否回滚。

冷启动时从内容目标和品牌受众选择选题，不声称“学会平台算法”。数据充足后，可以测试 70/20/10 已验证/相邻/探索选题混合；这是初始比例，不是平台推荐规律。

每次新主题先进行语义去重、已用镜头/字幕重复检测、事实依据检查。周报将“事实、可能原因、下一次实验”分别写明，重大账号定位变化应交给用户确认。

## 9. 内容栏目与图文制作

栏目模板：真实产品功能教程、用户问题解答、效率技巧、软件设计故事、版本更新（必须真实）、场景痛点、CG 视觉展示、功能限制透明说明。除重要节点外，不建议天天制作高成本三维广告。

图文 ContentPackage：`topic_id`, `headline_variants`, `body_platform_variants`, `asset_ids`, `claim_evidence_ids`, `tags`, `ai_content_declaration`, `review_state`, `version`。

图文编辑器支持：左素材区、中央画布、右侧标题/文案/封面属性、版本对比、局部修改、导出 PNG/JPG、保存草稿、复制标题与正文、通过规则检查。不同平台需要差异文案和尺寸预设，但这些仅是**创作规格**，不包含发布动作。

## 10. 全类型 AI 宣传视频工作室（本版核心修订）

> **产品定义**：不是 CG 专用工具，而是能制作多类型商业宣传视频的 AI 导演与制作系统。CG 是可选镜头类型。每个创作者根据品牌真实资料、用户目标、已有视频风格、成本和平台规格自动挑选最适合的形式，并在同一工程内混合多个制作引擎。发布仍然**仅由用户本人完成**。

### 10.1 视频类型与交付要求

| 视频类型 | 常见表现 | 推荐底层 | 是否可混搭 |
|---|---|---|---|
| 2D / MG 动态图形 | 动态文字、几何动画、信息图、科技感图解 | Motion Canvas、OpenFilm 的 SVG/CSS/Canvas | 是 |
| 3D / CG 商业动画 | 设备悬浮、三维产品、科幻灯光、粒子/轨道镜头 | Blender + MCP、Three.js、OpenFilm | 是 |
| 卡通 / 插画 / 漫画短片 | 漫画分镜、角色动画、动画风格故事 | 用户授权插画 + ComfyUI/Wan 图片/视频生成、OpenFilm 合成 | 是 |
| 真实软件操作演示 | 屏幕录制、点击放大、UI 讲解、对比教程 | 用户上传录屏、OpenFilm、FFmpeg | 是 |
| 素材混剪与解说 | 视频素材、字幕、旁白、图卡、节奏剪辑 | MoneyPrinterTurbo、OpenFilm、FFmpeg | 是 |
| AI 创意广告镜头 | 文生视频、图生视频、抽象场景、风格化转场 | ComfyUI + Wan 2.2 / 合规第三方视频 API | 是 |
| 混合式品牌广告 | 上述形式按分镜组合（推荐） | **统一 Timeline / Shot Provider 系统** | 核心 |

V1 重点实现 **2D/MG、录屏演示、素材混剪、AI 生成素材接口、混合式视频** 五个模式；3D/CG 和连贯卡通人物列为可选增强。界面不限制用户只能选一个风格，允许“整片 AI 自动推荐 + 单镜头改制作引擎”。不用真人作为默认视频类型，但允许用户提供合法的真人出镜素材以供混剪，不强迫或默认生成拟真人物。

**许可处理原则**：每个引擎、节点、视频模型权重、背景音乐、配音模型、商用字体、图库素材、真人/角色肖像分别记录 `license_id`, `permitted_use`, `source_url`, `credit_required`, `attribution`, `expires_at`, `restriction_flags`。未经核实，不展示“商业可用”标识。HiveMtk 仅补充客服/运营/审核功能，与视频引擎相互独立，不接入其自动社媒发布模块。

### 10.3 统一的镜头资产协议（Scene IR）

```json
{
  "video_project_id": "promo_001",
  "campaign_goal": "software_signups",
  "duration_sec": 30,
  "aspect_ratio": "9:16",
  "creative_direction": "AI 自动推荐，科技感但真实可信",
  "shots": [
    {"shot_id": "s1", "engine": "motion_canvas", "type": "motion_graphics", "duration_sec": 4, "assets": ["brand_logo"], "voiceover": "面试前还在临时准备吗？"},
    {"shot_id": "s2", "engine": "openfilm", "type": "screen_demo", "duration_sec": 7, "assets": ["verified_recording_01"], "fact_refs": ["product_fact_15"]},
    {"shot_id": "s3", "engine": "comfy_wan", "type": "ai_creative_scene", "duration_sec": 5, "assets": ["licensed_style_ref_01"], "origin": "synthetic_visual"},
    {"shot_id": "s4", "engine": "openfilm", "type": "montage", "duration_sec": 8, "assets": ["screen_recording_02", "licensed_broll_01"]},
    {"shot_id": "s5", "engine": "motion_canvas", "type": "cta", "duration_sec": 6, "assets": ["brand_logo", "brand_domain"]}
  ],
  "delivery": {"format": "mp4", "resolution": "1080p", "subtitles": true, "ai_marking_review": true, "manual_publish_only": true}
}
```

此结构是**拟开发项目内的中间协议**，不是任一开源项目原生提供的可直接调用 API。实现时把 `Scene IR -> Provider Adapter -> Clip Assets -> OpenFilm/FFmpeg` 编排成稳定任务，允许一个镜头使用生成模型、下一个镜头使用真实录屏。`fact_refs` 是产品功能真实性校验依据，`origin` 记录合成来源与 AI 标识要求。对场景生成保留原始提示词、seed、模型版本与成本。

### 10.4 智能导演 Agent 的分镜决策

`MarketingBrief -> ScriptAgent -> StoryboardDirector -> StyleSelector -> ShotProviders -> TimelineAssembler -> AudioSubtitles -> QualityGate -> ManualPublishPackage`。

**StyleSelector 不只是按关键词挑模板**，还需考虑：受众偏好、内容类型、目标转化、用户素材是否齐全、是否存在真实产品演示要求、模型效果是否可控、成本预算、版权与平台规则。根据这些因素给出 2~3 个方案，默认推荐一个低成本且可信的方案；用户可锁定风格/素材/镜头，Agent 不得擅改。

**六种基础创作模板**：功能讲解、用户问题解答、教程演示、品牌故事、软件版本更新、品牌形象广告；模板不是制作引擎，某个模板可以使用多种引擎混合渲染。

**制作顺序**：先旁白与分镜大纲 → 生成低分辨率 storyboard/animatic → 用户或 Agent 做预算/质量判断 → 高质量镜头渲染 → 统一音量、色彩、字幕、配乐 → 关键帧检查 → 用户审阅。生成式视频成本必须在调用前展示预计区间，并允许替换为廉价镜头。

### 10.6 核心质量检查与风险

- **事实**：软件 UI 必须是上传的真实界面；不允许 AI 重绘虚构按钮/软件结果；AI 创意镜头不得冒充真实产品功能。
- **视听**：黑帧、字幕错位、裁切、时长、卡顿、配音不清、BGM 过大、字幕安全区域。
- **一致性**：卡通人物/画风、产品 Logo、字体、包装、品牌色，生成式场景必须保持设定一致。
- **版权**：外部图库授权、声音肖像、音乐、商用字体、模型权重和工具许可证分别记录。
- **AI 标识**：保持源素材归属；生成/合成片段及整片发布标识在发布包中提供提醒，用户在官方平台按要求声明。
- **数据保护**：默认不把未公开的真实产品截图、账号后台、客户聊天记录发送给外部生成模型；需单独同意和脱敏。
- **失败容错**：镜头失败可替换制作引擎，但不能绕开真实功能和版权检查；预算触顶时停止或只生成低成本草稿。

### 10.7 里程碑与验收

**PoC（必须在 M0 完成）**：同一条 20–30 秒软件宣传片至少包含两种不同引擎的镜头（例如 Motion Canvas MG 开场 + 录屏演示 + OpenFilm 素材混剪），能导出 MP4 且镜头可局部修改。

**V1**：至少 5 类视频模式可选，具有“AI 自动推荐 + 手动指定引擎”的双入口；图文/视频素材绑定许可证；1080p、9:16/16:9/1:1；能生成合法合规的用户手动发布包；整套流程连续运营可触发，不是单次生成孤岛。

**V2**：引入 ComfyUI/Wan、Blender 等高成本引擎，实现角色一致性、多参考图、动作/风格迁移和更复杂的三维动画；部署前审查商用模型权重、算力与素材隐私，不承诺所有模式在用户本地无 GPU 时免费运行。

## 11. 全新“人工发布中心”设计

### 11.1 四个页面
- **待发布**：卡片列出平台、内容标题、预览、状态、待办次数；点击“查看发布包”。
- **发布包详情**：视频/图文/封面文件、标题、简介、话题标签、合规报告、版权/AI 标识提示、复制/下载按钮。
- **手动发布指引**：列出平台官方应用内的通用步骤与最后核对事项；按钮仅可打开经核实的官方入口，不可代替上传/点击发布。
- **发布登记**：用户输入发布时间、平台作品链接（可留空）、发布证明、备注；保存为 `user_reported_published`，支持纠正和撤销登记。

### 11.2 出口边界
```
AI Create → QualityCheck → ComplianceCheck → UserReview
  → MakePackage(assets + copy + checklist + declarations)
  → Download/Copy/OpenOfficialWebsite
  → USER manually publishes
  → USER returns & marks published
  → ImportMetrics → NextStrategy
```
**软件内部不含 `publish.submit()` 等触发第三方发帖工具**。`openOfficialWebsite` 不预填账号、不自动粘贴正文、不触发后台指令，仅打开网页；对于需要移动端 App 的平台显示手动打开引导。

### 11.3 数据模型
- `manual_publish_packages`: `id`, `creator_id`, `content_version_id`, `platform`, `files_manifest`, `copy_bundle`, `compliance_report_id`, `prepared_at`, `status`。
- `manual_publish_records`: `id`, `package_id`, `platform`, `user_reported_at`, `user_entered_url`, `user_evidence_asset_id`, `source='user_reported'`, `recorded_by`, `recorded_at`, `corrected_at`。
- `publish_reminders`: `id`, `package_id`, `due_at`, `delivery_channel`, `state`, `dismissed_at`。

历史数据若从旧版迁移，`platform_publish_status` 不能直接映射成真实已发布状态，需显示“旧版本待核对”，要求用户重新确认。

## 12. 平台合规引擎（人工发布前置）

**多层审核**：
1. 确定性规则：危险品/违法信息、格式限制、平台字段长度与品牌禁词；规则带来源、核验日期和版本。
2. 语义规则：虚假宣传、夸大承诺、未证实功能、虚构好评、误导性 AI 形象、站外导流风险。
3. 媒体审查：字幕与旁白、视频关键帧、真实 UI 与来源、素材版权、音乐许可、视觉 AI 标识。
4. 人工发布核对：平台最新实际规则、账号主体适用性、适用时的 AI 内容显式声明/平台标记、作品标题与营销内容一致性。

结果 `pass_precheck`、`needs_revision`、`needs_human_review`、`blocked`、`unknown`；**不命名为“平台已审核通过”**。审核接口失效时不能自动标记通过。用户手动发布前仍应复核官方平台最新要求。

中国人工智能生成合成内容标识相关规定在适用场景中可能涉及显式/隐式标识和平台声明；具体实施以现行法律与对应平台官方规则核实为准。发布包默认提供“AI 素材来源说明/标识检查清单”，不承诺一套标识覆盖全部平台。

**安全暂停**：重大版权问题、明显虚构功能、违规营销风险、合规审查超时、用户预算上限、素材来源未确认时，停在“待修订”，AI 不会为完成日更而忽略风险。

## 13. 数据导入与成长回路

**主要数据渠道**：用户导出官方分析报表（CSV/XLSX，先示例校验再导入）；手动输入播放/阅读/收藏/点击/咨询等数字；自有官网的合法访问/注册数据。用户可选择定期导入或只反馈“内容有用/需要修改”。V1 不自动读取社媒后台数据。

字段须包含 `platform`, `content_version_id`, `metric_name`, `metric_value`, `period_start`, `period_end`, `observed_at`, `data_source`, `import_batch_id`, `quality_flag`。不同时长窗口和平台指标不可直接比较；缺失不填 0，记录 NULL/unknown。用户撤销或修正统计后，学习任务产生新版本。

**每周学习报告**输出：观察到的事实、可靠性、内容主题表现、素材/格式表现、真实用户反馈、下周新选题与具体原因、风险、不足数据和建议 A/B 实验。用户可以接受/拒绝重要策略变化；留回滚记录。

### M4 强制“零自动发布”测试
- 静态扫描不含社媒发布 SDK、浏览器自动提交脚本与用户登录态存取逻辑。
- 网络出口审计：执行完整“生成→发布包→登记”流程时，无向第三方社媒发帖地址的 POST/PUT/PATCH。
- 产品中所有外部平台按钮仅打开用户可见的官方页面，不自动触发上传或点击发布。
- 标记“已发布”必须由用户主动操作，且标明“用户登记/未官方核验”。
- 数据导入只能来自用户主动上传/填写或未来经独立评审启用的合法接口（此版本不实现）。

### 端到端验收
从真实品牌资料输入 → 创作者保存 → 7 日模拟自动生成选题 → 图文与 30s 混合风格视频真实渲染 → 内容预审 → 准备素材包 → 用户手动发布登记 → 导入两批真实/测试来源分明的统计数据 → 周复盘生成下一轮选题。任一环节失败，有状态、有原因、有重试或人工处理入口。

## 21. 商业模式与成本

自由试用功能有限；面向独立创作者提供基础订阅，专业视频生成与高成本模型计入额外额度。定价可从 39–59 元/月、99–149 元/月等假设开展用户访谈，但不直接视为有效市场价格。避免“9.9 元永久不限量视频”的不可持续承诺。

成本拆成 Token、图像工具、TTS、CPU/GPU 渲染、文件与带宽；日/月预算由用户设置，AI 不得自动提高额度；可选使用用户自己的 API Key，但必须提示模型供应商的数据处理条款。

## 22. 性能、隐私与无障碍

- 任务历史长期保留但支持用户删除与导出；素材需租户隔离与到期回收。
- 视频项目加载先展示低清预览与镜头缓存，最终导出再高清渲染。
- 支持键盘导航、焦点状态、表单错误语义、色弱可辨状态、Reduced Motion 模式。
- UI 标签不把“风险低”写成“平台保证安全”；AI 指标分析不把“用户填写”写成“官方已验证”。
- 个人隐私/品牌商业信息上传云模型需明示与最小化处理，优先用户授权后调用。

# V2.2 增量优化（已纳入当前产品方案）

# AI 持续创作者 V2.2 · 优化补充方案

> 基于 V2.1《AI 持续创作者 · 全类型宣传视频》开发文档所做的补充审查。此文档是**需求/设计变更建议**，并不表示代码已实现、UI 原型已更新，也不替代原版开发方案。
>
> 不变红线：AI 负责持续策划、图文/任意类型宣传视频制作、预审、资料打包与数据分析；用户在第三方平台官方客户端手动发布。绝不自动登录、上传、点击发布、批量私信、模拟真人互动，不能宣称人工发布保证不封号。

## 0. 当前版本最重要的结构风险

V2.1 已有选题日历、多引擎宣传视频 Scene IR、基于用户导入数据的学习、人工发布工作流。但存在以下未形成完整产品契约的环节：

1. 品牌知识库以初始用户上传为主，缺少软件版本变更的可靠发现、事实待核实与过期资产下线制度。
2. Scene IR 示例只表达镜头的时长与引擎，没有规定无损编辑、镜头局部修订、素材变更传播、渲染缓存、撤销/版本迁移和编辑能力差异。
3. 视频技术 QA 已覆盖黑帧、字幕、Logo 等，但高成本渲染之前的创意质量门槛、内容差异度与人工偏好学习还不够明确。
4. 反馈学习偏重平台数据，忽略用户逐项修改脚本/封面/镜头的高价值反馈。
5. 缺少成品交付能力的边界：生成视频的“参数级可编辑”和“只能重新生成片段”应分别标记。
6. 模型费用、音视频版权、上传隐私和生成内容来源缺少贯穿各处理阶段的完整证据链与失败回滚测试。

## 1. P0：产品动态感知与真实功能证据层

### 需求

新增 `ProductChangeMonitor` 与 `BrandFactReview`：在用户明确授权后，从公开仓库、指定文档、产品更新日志或用户上传的版本说明获取变更；生成“发现变更”而非直接发布营销事实。允许用户逐条批准后，才升级为可宣传的事实。

### 数据契约

- `product_sources`: 连接类型、源 URL/仓库、授权状态、采样方式、最后成功检查时间。
- `product_change_events`: 来源版本、变更差异、首次观察时间、置信度、是否影响用户可见功能。
- `brand_fact_claims`: 文案声明、证据 ID、版本范围、验证状态（`proposed|verified|rejected|expired`）、审核人。
- `asset_applicability`: 素材适用产品版本、过期风险、是否已发布。

### 验收

- 用户提交一个新版产品说明，其中新增功能尚未发布：AI 只能提出“待验证新功能选题”，不得自动生成“已上线”宣传。
- UI 版本升级后，旧截图被标记为过期，所有引用它的**待发布稿**进入复核。
- 无授权时不扫描用户私有仓库。

## 2. P0：统一视频工程格式、能力声明与无损编辑

### 需求

保留 V2.1 的 `Scene IR`，扩展为 `VideoProjectIR v1`，并将渲染厂商/框架视为 Provider。不要将 OpenFilm 的私有工程格式作为不可替代的存储真相；可以直接采用它的渲染、编辑与预览能力，但由独立的领域模型保存工程语义。

### 示例契约

```json
{
  "schema_version": "1.0",
  "project_id": "promo_001",
  "brand_version": "v2",
  "revision": 7,
  "canvas": {"width": 1080, "height": 1920, "fps": 30},
  "timeline": [
    {
      "shot_id": "s2",
      "shot_revision": 3,
      "kind": "screen_demo",
      "provider": "openfilm",
      "start_frame": 120,
      "duration_frames": 210,
      "sources": [{"asset_id": "screen_001", "sha256": "...", "fact_id": "product_fact_15"}],
      "editability": "parametric",
      "params": {"zoom": 1.25, "caption": "使用真实界面演示"},
      "render_cache_key": "...",
      "provenance": {"license_status": "verified", "synthetic": false}
    }
  ]
}
```

- `editability`: `parametric`（文字、图层、动画参数可改）、`clip_level`（只能裁切、变速、调色等）、`regenerate`（需重新生成图像/视频）三类。
- 时间轴的帧数、帧率、音轨采样率需标准化，不要仅用浮点秒数存跨工具镜头边界。
- 修改单镜头只使该镜头及受影响的转场/混音缓存失效；其余成品缓存保留。
- 用户锁定的镜头、品牌事实和素材，不允许 Agent 在全片调整时擅改。
- OpenTimelineIO 可以作为可选的剪辑交换格式；它不是视频渲染引擎，不能用它代替 OpenFilm/FFmpeg。

### 验收

- 30 秒 5 镜头成片，修改第 3 镜头字幕后，只有第 3 镜头与相关合成步骤变化；未更改镜头的哈希与原始资产不变。
- AI 视频生成镜头在 UI 标为“片段可编辑/重新生成”，而非虚称“所有元素均可自由编辑”。
- 保存、重启、恢复和撤销 3 个连续编辑版本，成片一致且素材引用不丢。

## 3. P0：分层质量门 + 创意评分 + 内容新鲜度

创作顺序：品牌事实校验 -> 脚本草案 -> 创意评审 -> 分镜 Animatic -> 成本预估 -> 低清预览 -> 高成本镜头渲染 -> 视频技术 QA -> 合规预审 -> 待用户审阅。

`CreativeQualityReport` 包含：开头是否清晰、是否聚焦单一核心利益、产品证据覆盖率、近 30 条主题重复风险、近 10 条镜头语言重复率、表达过度广告化风险、受众匹配与是否有明确用途。

质量评分不能作为流量预测。设置 `blocked_by_facts` / `needs_rework` / `human_review` / `ready_for_preview`；素材版权和夸大宣传属于硬门禁，不能被高创意分抵消。

在日更质量不足时，允许**跳过/提前准备替代稿**，不要为了凑数自动发布低质或不实内容。

## 4. P0：将用户修订作为反馈学习第一来源

新增 `edit_feedback_events`：`content_version_id`, `editor`, `before`, `after`, `element_type`, `reason_tag`, `user_locked`, `observed_at`。

给用户可选的一键原因：“太像广告”“不准确”“节奏太快”“需要更真实”“视觉不统一”“希望更短”“其他”。用户不必每次填写原因；可由 AI 提出归纳，用户确认后才固定为稳定品牌偏好。

每次周复盘分别输出“来自平台真实数据的趋势”“来自用户修改的风格偏好”“无数据，仅为待验证假设”。

验收：同一用户连续 3 次删掉夸张开场，新作默认先给克制版，且可以解释这一倾向来自用户明确修订。任何用户锁定偏好都可撤销。

## 5. P0：预算优先的多引擎生产调度

模型/渲染器提供 `ProviderCapabilities`（输入、输出、格式、分辨率、单次预计费用、费用模型、版本、许可证、当前可用性、可编辑等级、数据驻留地、最高处理时长），统一调度器根据目标质量、素材来源、版权和预算选型。

优先顺序：**真实授权素材/已存在缓存 > 可编辑 MG / 程序化动画 > CPU 普通渲染 > 生成式视频/GPU 高成本镜头**，但不牺牲用户指定的创意目的。

- 预算预留/结算必须原子化、可审计；可设置每次渲染最大预算。
- 生成失败可换引擎的前提是用户允许且画面语义不变；不可悄悄把真实产品演示替换成合成 UI。
- 对源文件/提示词/模型版本/seed/输出设置生成内容哈希，用于缓存；生成模型有随机性时，必须显式管理 seed 与重生成语义。
- 预览先低分辨率与水印（仅内部），审核后再高清导出。

验收：故障注入导致第三镜头渲染失败时，只重试该镜头；账单不重复扣费，用户看到精确失败原因和当次费用。

## 6. P1：可证明的素材来源和生成内容标识

每个可发布成品构建 `AssetProvenanceGraph`：原始截图/录屏、生成素材、引用音乐/字体、处理引擎和版本、用户上传证明、许可/署名与最终工程输出。

可选引入 CAI 的开源 **C2PA SDK**，为支持的媒体类型创建/验证内容来源凭据，并把用户应该在平台上勾选的 AI 创作声明列入“人工发布包”。注意：C2PA 签名是来源与完整性线索，**不等于证明视频所述事实真实，也不能替代平台 AI 标识要求**。

验收：随机选一条导出视频，可以追溯到所有所用素材、许可及合成模型；上传数据给云端模型前明确授权。

## 7. P1：人工发布交接进一步产品化

V2.1 的人工发布机制保持不变，新增：
- 发布包的**移动端交接页**（下载文件、复制分平台标题/话题、查看 AI 标识声明提醒）。
- 设备间文件传递通过本软件授权下载或用户自行保存，不驱动社媒 App、自动粘贴或点击提交。
- 支持“已发布/暂缓/平台拒绝/放弃”的用户自报结果；不可将“用户标记”称为“平台 API 已核验”。
- 每个平台的内容规范有来源、核验日期、适用账号类型、最后更改时间；过期规则提示用户到官方页面重新确认。
- 可在用户授权下发送**本软件自己的通知**提醒待办；不使用平台私信来提醒。

## 8. P1：长期运营不是只能每天产一条

新增创作配额策略：`min_quality_threshold`, `weekly_content_mix`, `reserve_content_count`, `content_reuse_policy`, `review_cadence`, `time_off_days`。

建议引入 **7 天预备库存**：日常先生成少量低成本候选及审核通过的备用图文，高清视频仍按预算/重要性生产；用户停止发布或请假时继续储备草稿但不外发。

对软件更新内容设置更高的时效性优先级，重大功能变化允许调整已经排好的内容日历，但更改须留历史与原因。

## 9. P1：可观测的商业效果，避免“自成长”空口承诺

区分三个指标：
- 运营生产力：用户花费审核/修改时间、单次合格内容成本、按周有效内容数。
- 内容质量：用户首次通过率、质量分/用户评分一致性、重复率、真实性/版权风险率。
- 营销效果：只能使用用户合法导入或自有站点授权数据；按平台+时窗比较，不同源数据不得混加。

**不要把播放量视为唯一目标。** 用户改变标题/视觉时，保留从旧版到新版的影响链；数据不足时使用未确定标签，不作超强因果推断。

## 10. P2：简化商业交付和工程复杂度

先交付“一个品牌、一个持续创作者、三种可运行的制作方式”：
1. 软件录屏+动态图文。
2. MG 动画宣传片。
3. 视频素材混剪。

先支持“AI 推荐与用户单镜头调整”，再接云端视频生成；最后才上线复杂 3D、连贯卡通人物生成、跨品牌 CRM 和 GEO。V1 可展示扩展入口，但**不可将未接通功能标记为可用**。

保留独立 Worker 接口与工程契约，不要为每个新视频生成器新建一套前端编辑器。

## 11. 最终开发优先级与依赖

| 顺序 | 能力 | 依赖 | 完成门槛 |
|---|---|---|---|
| 1 | 真实产品事实与来源版本 | BrandStore | 产品更新不会悄悄变成未经验证的声明 |
| 2 | SceneIR v1 与局部编辑测试 | VideoProjectStore | 可修改单镜头、恢复编辑、准确区分编辑等级 |
| 3 | 创意评审与低清预览 | SceneIR + QualityReport | 复杂制作前发现明显问题 |
| 4 | 预算路由/缓存/可观测 | Providers + Ledger | 重试不重复扣费；高级引擎可选 |
| 5 | 用户修订学习 | ContentVersion + EditEvents | 偏好迭代有用户证据 |
| 6 | 移动端人工发布交接 | ManualPublishPackage | 无第三方发帖请求，仅用户手动发布 |
| 7 | 周期复盘和稳定运行 | Scheduler + MetricsImport | 连续 14 天可恢复，可解释学习 |
