# AI 工程治理落实任务（给 Codex 的分阶段验收）

| 任务 | 开发内容 | 验收证据 | 优先级 |
|---|---|---|---|
| ENG-001 | 建立 `AGENTS.md` / 模块索引 / `PROJECT_STATUS.md` | AI 可以根据故障编号定位模块及代码 owner | P0 |
| ENG-002 | 统一 Request/Trace/Run/Shot/Error IDs | API+Agent+Worker 能串联完整 trace | P0 |
| ENG-003 | 错误码与诊断 Schema | API 错误返回含稳定错误码及用户友好建议 | P0 |
| ENG-004 | 独立日志/指标/追踪 | 失败镜头能找到首个错误和真实来源 | P0 |
| ENG-005 | 工具权限与业务禁令 | 自动化测试证明无社媒自动发布模块 | P0 |
| ENG-006 | 最小可复现 Bug 工作流 | 新 Bug 均附失败样例或证据，不以猜测代替根因 | P0 |
| ENG-007 | 基础 CI/代码检查 | PR 必须通过实际测试、静态/权限/契约检查 | P0 |
| ENG-008 | Release Manifest / 版本冻结 | 每个运行任务可追溯实际 Git/Prompt/模型/IR 版本 | P0 |
| ENG-009 | 长任务/数据库兼容与回滚 | 迁移及旧任务恢复演练记录 | P0 |
| ENG-010 | 视频渲染黄金样例 | 三种真实 MP4、编辑/缓存/版权回归 | P0 |
| ENG-011 | 运维诊断 UI | 权限分层、脱敏查询、错误/版本证据页 | P1 |
| ENG-012 | 自动依赖更新 PR | 周期更新、检查风险、无自动合并生产 | P1 |
| ENG-013 | 备份/PITR/恢复检查 | 用备份环境成功恢复一套创作者数据 | P1 |
| ENG-014 | Agent/Prompt 评测 | 固定数据集对比与指标、失败样本 | P1 |
| ENG-015 | 线上告警与 SLO | 合理报警阈值、责任人和演练 | P1 |

**禁止误报**：工程治理包目前仅为设计、示例和离线原型；上述任务只有在实际仓库中完成真实接线与测试才能标记成功。建议 ENG-001/002/003/005/007/008 作为原 M0 前置条件。
